LLM 上下文工程观察：RAG、记忆与 Harness

RAG 为当前任务检索证据，Memory 保留可跨会话复用的状态，Harness 管理检索与工具调用的权限、预算和结果验证。

Written with Gemini.

一、一次数据分析需要哪些上下文

假设用户请 Agent 按财年汇总收入，并要求这个项目以后默认使用财年口径。Agent 要从财务文档和已有查询中找到当前适用的财年定义，也要把用户确认的默认口径保留给下次会话。执行前，它要检查数据访问权限和查询的只读约束，交付时还要核对取数日期范围。

这里有三个职责。RAG 为当次任务查证据。记忆系统（Memory） 管理跨会话沿用的项目约定。Harness 是控制 Agent 执行的运行层，负责决定该查什么、能读什么，以及如何验证动作和结果。

长上下文扩大了模型的工作空间。长任务仍然需要为证据和历史分配 Token，处理信息过期与冲突，并约束工具的访问范围。

二、RAG：从单次召回到按需检索

2.1 以向量检索作为基线

Lewis 等人在 2020 年提出结合检索器和生成器的 RAG 模型，分别按序列和按 Token 使用检索到的文档 [1]。一种常见的工程基线是按固定长度切分文档，建立向量索引，召回 Top-K 个片段并放入 Prompt。在 FAQ 和语义明确的知识库问答中，可以用这个基线衡量更复杂的检索是否值得投入。

复杂任务会暴露单次相似度召回的几个局限。

  1. 切块可能破坏文档边界。 跨章节论证、表格和代码依赖需要保留相应结构。
  2. 相似度只衡量部分相关性。 关键词适合精确标识符，向量适合语义匹配，跨文档关系常要沿目录或关系索引进一步查找。
  3. 召回后仍要分配上下文预算。 证据可能排序过低，被截断，或被重复内容掩盖。信息位置与干扰也会影响模型对长上下文的利用 [2]。
  4. 各阶段需要单独定位故障。 查询改写、召回、重排、上下文组装和生成都可能影响最终结果。

2.2 研究中的三种检索改进

调整检索单元。 Dense X Retrieval 将检索单元从段落细化到命题。Late Chunking 先编码整篇文档，再生成带有文档上下文的块向量。两项研究都提示，切分粒度和文档结构会影响模型找到证据的能力 [8][9]。

按任务选择检索步骤。 Self-RAG 用反思标记学习何时检索、如何评价结果。Adaptive-RAG 按问题复杂度选择直接回答、单步检索或多步检索。多步检索能补充候选证据，也会增加模型调用和延迟 [10][11]。

在构建期和查询期分配成本。 RAPTOR 预先构建多层摘要树，GraphRAG 预先建图和生成社区摘要。SAG 在查询时按共享实体连接相关原文块。SAG 是预印本，实验覆盖三个多跳问答基准 [3][12][13]。

RAGAS 提供回答评估维度，Seven Failure Points 分类检索到生成链路中的工程故障。对执行任务的 Agent，还应检查权限、接口和业务规则是否满足。评测设计见第五节 [14][15]。

2.3 检索设计的三个工程决策

决策可选设计适用场景主要成本与失效模式
怎样找候选组合关键词、向量、元数据过滤和重排精确术语和语义查询并存的知识库维护索引，调试召回与排序
怎样组织证据关系用目录树保留层级，用图索引关联实体、调用和引用长文档导航、代码依赖、多跳问答、全库主题总结构建和维护结构，检查漏边、错误关系与错误路由
何时继续检索先读目录或摘要，根据缺口扩大范围或读取原文大型代码库、研究任务、长程 Agent在线延迟和调用次数随任务变化

这三个决策可以组合。PageIndex 根据文档树逐层导航，无需向量数据库或固定长度切块。OpenViking 用类似文件系统的接口组织知识、记忆和技能，支持从摘要、概览逐层打开原文，并在目录范围内做语义检索。Graphify 则对代码、文档构图，并区分直接抽取和推断得到的关系 [4][5][6]。

全库主题总结可以评估 GraphRAG 的社区摘要是否提高证据覆盖。查找精确配置项可以先测关键词检索的命中率和延迟。是否引入树或图，取决于查询分布和语料更新频率 [3]。

2.4 渐进式披露与检索停止条件

渐进式披露（Progressive Disclosure）先提供目录或摘要，再按需呈现详细内容。多步检索可以据此从低成本的信息入口开始，在证据不足时逐步查阅原文。

TEXT
问题与任务状态
    ↓
读取目录、摘要或实体索引
    ↓
选择候选范围，查阅局部证据
    ↓
检查必要证据是否齐全，是否存在冲突
    ├─ 证据充分 → 带来源作答
    ├─ 证据不足，仍有预算 → 改写查询、换路或展开下一层
    │                     └→ 回到证据检查
    └─ 证据不足，预算耗尽 → 说明缺口、给出有依据的部分结论或转人工

例如，核对财年收入至少需要确认财年起止日、收入定义和适用范围。把这些条件列入检查项，再用轮次、Token 和时延限制检索。树导航选错分支时，可以回退到关键词或向量检索。进入上下文的证据应保留文档版本和页码或代码位置，便于读者复核。

三、Memory：管理跨会话状态

3.1 区分上下文、证据和工作流状态

本文用 RAG 指向为任务检索外部资料的流程，用 Memory 指向跨会话状态的管理。两者可以共用关键词或向量检索。各自的职责由数据来源、写入权限和有效期决定。

机制数据来自哪里主要作用
长上下文当前请求、会话历史和临时载入的资料提供一次推理的工作空间
RAG文档、网页、代码库中的外部知识找到当前问题所需的证据
Memory对话、操作轨迹、显式偏好与复盘跨会话复用经过筛选的状态与经验
Checkpoint / Run State任务变量、执行位置、工具结果恢复某次工作流的执行进度

3.2 记忆的生命周期

Agent 的记忆可以按用途分为工作记忆、情景记忆、语义记忆和程序性记忆。工作记忆通常保存在当前上下文或运行状态中，其余三种可以按需持久化 [16][17]。

类型典型内容推荐保存方式主要风险
工作记忆当前计划、临时变量、正在处理的证据当前上下文或任务状态，随会话清理把临时假设误写成长期事实
情景记忆某次故障、修复过程、历史决策及其原因带时间和来源的事件记录，可压缩但保留追溯链流水账膨胀，旧事件覆盖新状态
语义记忆稳定偏好、项目约定、已确认事实可更新、可失效的结构化记录冲突、过期、把推测当事实
程序性记忆已验证的操作步骤、可复用技能与检查清单版本化 Skill、脚本或流程，并附适用条件在新环境中机械复用旧流程
  1. 候选写入 从用户显式要求、已验证的任务结果和有复用价值的事件中提取候选。
  2. 提炼与校验 区分观察、推断和用户确认，剔除敏感信息与无复用价值的中间输出。
  3. 合并与冲突处理 去重，保留时间范围、版本和来源，区分适用的项目与时间段。
  4. 检索与注入 在已授权的用户、项目和团队范围内召回，在 Token 预算内组装上下文。
  5. 反馈与遗忘 支持更正、过期、删除和审计，让失效的记忆退出默认召回。

以前文的报表为例，用户确认「本项目默认使用财年」后，系统可以把它写成带项目范围和生效时间的偏好。下次先取回这条偏好，再从现行财务文档确认财年起止日。用户改用自然年时，把新口径另存为一个版本，旧版本退出默认召回，并按保留策略处理。

3.3 记忆项目的不同侧重点

  • AgentMemory 面向编码 Agent，支持跨工具捕获会话、查阅和管理项目历史。无密钥模式支持 BM25，向量和图检索取决于配置与可用数据 [20]。
  • claude-mem 捕获 Agent 活动，并生成观察记录和会话摘要。新会话用「索引—时间线—详情」分步检索历史 [21]。
  • Mem0 提供面向用户、会话和 Agent 的通用记忆 API，支持托管与自托管 [22]。
  • OpenViking 通过同一上下文文件系统组织知识、记忆和技能 [6]。

比较这些项目时，需要先对齐负载。会话捕获重在追溯，用户个性化重在偏好更新，技能复用重在适用条件。报告基准结果时，注明版本、模型、数据和预算。

3.4 持久化带来的风险

陈旧文档或错误索引会使 RAG 在多次查询中重复出错。记忆系统还能把模型生成的推测或工具带回的信息写入长期状态，让它们在后续会话里反复被当作事实。

  • 错误固化 区分模型推断和用户确认，写入时保留来源与验证状态。
  • 过期与串域 根据作用域和有效期召回，支持更正和版本替换。
  • 持久化提示注入 在写入时检查来源。检索结果作为数据交给模型，工具权限由 Harness 单独检查。
  • 隐私与合规 采集时裁剪敏感内容，明确保留期，并支持查看、导出和删除。删除应覆盖派生摘要与检索索引。

四、Harness：把检索、记忆与执行连起来

Harness 在读取时限定检索范围，在执行时校验工具调用，在交付前检查结果。写入路径决定哪些信息能从本次任务进入长期记忆。

读路径

TEXT
用户请求 + 当前任务状态
    ↓
Harness 选择知识、记忆或任务状态，并在检索前限定授权范围
    ├─ 需要证据 → 在授权范围内查知识或记忆 → 复核来源、排序、按预算组装
    └─ 已掌握所需信息 → 直接使用当前上下文
    ↓
模型推理 → 检查工具权限和参数 → 调用工具（按需）
    ↓
验证答案或执行结果
    ├─ 满足任务约束 → 交付
    ├─ 证据不足，仍有预算 → 返回检索
    └─ 无法验证或超出预算 → 报告缺口或转人工

写路径在采集和落盘前裁剪敏感内容。短期事件日志按保留期管理。后台从获准保留的事件中提炼候选记忆，检查冲突与有效期，必要时请用户确认，再写入长期索引。项目事实尽量关联正式文档、测试或代码提交。

以财年收入为例，Harness 可以限制知识检索和数据库工具的项目权限，执行参数校验和只读约束，再按任务定义检查日期范围与结果格式。Jev 一类组件可以参与有界的路由判断。其部分判断接口提供概率字段，具体权限和业务规则仍由应用校验 [7]。

五、分层评估检索、记忆与任务结果

RAG 与 Memory 的评测都必须分层，否则无法知道收益来自哪里，也无法定位退化发生在哪一步。

层级RAG 重点指标Memory 重点指标
写入 / 构建文档解析成功率、结构完整度、索引新鲜度、构建成本写入准确率、重复率、来源覆盖率、敏感信息误存率
检索Evidence Recall@K、MRR / nDCG、重排增益、无答案拒识必要记忆召回率、过期记忆召回率、冲突识别率、跨域泄漏率
上下文有效证据占比、重复率、引用可定位率、Token 消耗有效记忆占比、作用域正确性、注入 Token 与详情展开成本
生成 / 执行答案正确性、忠实度、引用准确性、拒答质量个性化或任务成功率增益、错误记忆导致的失败率
系统成本P50/P95 延迟、检索轮次、缓存命中率、单次回答成本读写延迟、后台整理成本、存储增长、删除生效时间

RAG 对照可以比较无外部知识、直接给模型长文档、简单混合检索和结构化检索。Memory 对照可以比较无记忆、直接提供全量历史、会话摘要和完整记忆管线。各组使用相同的任务集和生成模型。固定预算时比较任务成功率，达到同一成功率时比较 Token、时延和维护成本。

组件指标用于定位退化。即使 Recall@K 提高，也要单独检查执行结果是否改善。LoCoMo 和 LongMemEval 可作为长程对话的评测入口。编码项目和企业应用还需要使用各自的真实任务验证 [18][19]。

记忆评测按会话时间推进，依次测试写入、召回和更正。可以验证用户更新偏好后是否沿用新值、删除后是否仍能召回、其他项目能否读到这项偏好。报告任务成功率时，同时记录错误记忆引入的失败。

六、两个待验证的工程问题

  1. 结构化索引何时值得维护？ 在同一批真实查询和语料更新记录上，对照简单混合检索。比较建索引成本、更新后的证据召回、端到端成本和任务成功率。
  2. 跨工具共享记忆何时有收益？ 让 IDE、CLI 和 Agent 复用同一组项目约定，记录任务成功率和重复确认次数。同步测试作用域隔离、偏好更正和删除生效时间。
